### Key Design Decisions
1. **`AbstractActionBean`** — Assigned to all 3 microservices as it is a pure web framework infrastructure class (implements `ActionBean`, provides context/messaging), required by every action bean in each domain
2. **`CatalogService`** — Kept in Catalog domain despite cross-domain usage (by Account and Cart); in a microservices architecture, Account and Cart services would call the Catalog service via APIs
3. **No unassigned classes** — All 26 classes in the application are covered across the 3 microservices
4. **Clear bounded contexts** — Each microservice has well-defined responsibilities with no anti-patterns (no god services, no chatty interfaces, proper data ownership)
