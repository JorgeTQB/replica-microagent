### Key Design Decisions

1. **`AbstractActionBean` assigned to all 3 domains**: It is a pure infrastructure base class with no business logic — provides `ActionBeanContext` management and message utilities via the Stripes framework. All 4 concrete action beans extend it, making it truly cross-cutting.

2. **No anti-patterns introduced**: Each microservice owns its data (separate DB tables per domain), has a clear single responsibility, and contains all necessary layers (Presentation → Business → Data → Domain).

3. **Cross-domain dependencies (e.g., `OrderService` using `ItemMapper`)**: In the microservices architecture, these would be resolved via REST API calls between the **Shopping Cart and Order Management** service and the **Catalog** service, maintaining loose coupling.
